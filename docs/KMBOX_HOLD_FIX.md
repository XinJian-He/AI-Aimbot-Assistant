# KMBox 静止按住后无法继续瞄准（2026-09-30）

对比项目：`E:\AIaim\最新稳定版\aim-QQLive-DML-Qt`。

## 代码证据

当前原代码的 `kmNet_monitor_mouse_*` 在 `GetTickCount() - s_hwTick > 2000` 时返回 -1；只有监听线程收到新报告才更新 s_hwTick。AimBackend 使用 `== 1` 判断按下，因此 2 秒无报告会关闭热键输出条件。鼠标移动或重新按键带来新报告后，条件又恢复。这与用户报告的恢复方式吻合；没有抓取硬件报文，尚不能把它宣称为实机验证结论。

Qt 版同样有监听超时，但 checkHotkey 优先用 GetAsyncKeyState，系统按住状态能够掩盖硬件监听的过期。当前按既有要求只用 KMBox 鼠标监听，因此修复不能简单照抄系统监听。

当前目标选择在每个推理帧上运行，旧轨迹丢失后可清除锁定，再由 switchReady 选择新轨迹，不要求热键重新出现按下边沿。MAKCU 的 Raw Input 状态也没有这个 2 秒超时。本次只修改明确发现的 KMBox 问题。

## 修改

- KMBox 鼠标按键采用原子状态缓存：仅由有效设备报告更新，不因静止无事件过期；未知状态保持 -1，调用处仍用 ==1。
- 监听停止、重连、切换执行设备、后端退出或监听错误时清空状态；旧监听线程结束后才启动新线程，避免旧线程清空新连接。
- 先绑定本地监听端口，再通知盒子报告；检查 bind、线程创建和命令响应。监听启动失败不再显示设备连接成功。
- 报文必须至少含完整鼠标/键盘状态且来源 IP 匹配，避免不完整报告覆盖缓存。仍沿用现有端口和 KMBox 协议。
- 不加入系统鼠标监听，不改目标优先级、追踪算法、MAKCU 或独家驱动路径。

手动重新生成整个解决方案 Release | x64 后，使用 KMBox：

1. 按住锁定键保持鼠标静止至少 5 秒；旧目标消失后出现新目标，应无需移动或重新按键即可继续瞄准。
2. 静止松开按键，确认输出停止；左右键、侧键分别测试。
3. 按住时断开/重连监听、切换设备，再次进入时不应继承旧按下状态；收到新报告前不触发。
4. 监听端口绑定失败时，界面应显示连接失败。

UDP 静默本身无法区分“没有输入事件”和“网络静默断开”。本次不伪造心跳、不回退系统输入：监听报错/显式停止会清状态，但单独丢失松开报文或静默网络中断时，最后状态可能保留到下一次有效报告或重连。若需要区分这两种状态，需要盒子支持并验证独立心跳/状态查询协议。
